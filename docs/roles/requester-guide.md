# Requester guide

A Requester is the person who asks for transport. This role is focused on creating trip requests, tracking them, and responding to change requests while the trip is still unplanned.

## What a Requester can do

- Create a request with a date and at least one stop
- Add a destination or purpose, including typed "Other" values when needed
- Edit or cancel their own request before a Scheduler starts planning it
- View the status of every request they own
- Ask for a cancellation after the trip has been assigned to a schedule

## Starting points

- My requests: review the current status of each trip request
- Request form: create or edit a trip request
- Bell / notifications: see updates relevant to your requests

## Typical workflow

### 1. Create a request

1. Open the request form.
2. Pick the trip date.
3. Add each required stop with a purpose.
4. Submit the request.

Notes:
- Dates 0–6 days ahead are Urgent.
- Dates 7 or more days ahead are Regular.
- A past date can only be entered by an Admin.

### 2. Track status

A Requester can see whether a trip is:
- Not yet scheduled
- Scheduled / waiting for approval
- Approved and assigned to a Driver
- Returned to the requester by a Scheduler
- Waiting on cancellation review

### 3. Edit or cancel while the request is still unplanned

Before a Scheduler starts planning the trip, the Requester can:
- update the details
- change stops or purpose
- cancel the request directly

Once a schedule holds the request, the right action becomes a cancellation request to an Admin instead of direct editing.

### 4. Follow up after scheduling

If the trip is planned but not yet complete, the Requester may be asked to review or confirm a cancellation request. They do not manage the schedule itself; the Scheduler and Admin handle the plan and approvals.

## Key guardrails

- A Requester never sees or updates another person's requests.
- A Requester cannot approve schedules or manage vehicles.
- Once a trip is on a live schedule, direct cancellation is not allowed; the workflow is admin-reviewed.
- Closed, finished, and locked trips remain read-only.

## Best practices

- Submit early when a trip may need scheduling coordination.
- Use a clear purpose and destination so the Scheduler can place it correctly.
- Check notifications after a Scheduler sends a request back or changes its status.
- If a trip is no longer needed, cancel it while it is still unplanned so the slot is not held unnecessarily.

## Quick checklist

- [ ] Create request with date and stops
- [ ] Confirm request appears under My requests
- [ ] Update or cancel before scheduling starts
- [ ] Watch for schedule or cancellation updates
